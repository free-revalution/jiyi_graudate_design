# 在线课程教育实验平台 — 毕业设计项目说明

> 本文档帮助你快速理解整个项目，应对毕业答辩。

---

## 一、项目是什么？

这是一个**在线课程教育实验平台**，面向高校师生。老师可以在线管理课程、布置作业、创建实训任务；学生可以在线选课、做作业、完成实训、查看成绩。

**通俗理解**：类似"中国大学MOOC"或"学堂在线"的简化版，但加入了实验/实训功能。

---

## 二、整体架构

项目采用**前后端分离**架构，一共三个独立的部分：

```
┌──────────────────────────────────────────────────┐
│                   用户（浏览器）                    │
│                                                  │
│    学生用 ──────→ 用户端前端（端口3000）            │
│    老师用 ──────→ 管理端前端（端口8848）            │
│                                                  │
│         它们都通过 HTTP 请求调用后端 API             │
│                      │                           │
│                      ▼                           │
│              后端服务（端口8080）                   │
│                      │                           │
│                      ▼                           │
│              MySQL 数据库（端口3306）               │
└──────────────────────────────────────────────────┘
```

| 部分 | 作用 | 端口 | 技术语言 |
|------|------|------|----------|
| **后端服务** | 处理业务逻辑、存取数据库 | 8080 | Java (Spring Boot) |
| **管理端前端** | 老师用的后台管理系统 | 8848 | TypeScript (Vue 3) |
| **用户端前端** | 学生用的课程学习网站 | 3000 | JavaScript (Vue 3) |
| **MySQL数据库** | 存储所有数据 | 3306 | SQL |

## 三、技术栈详解

答辩时被问到技术栈，按这个回答：

### 3.1 后端（Spring Boot）

| 技术 | 是什么 | 为什么用 |

| **Java 17** | 编程语言 | 企业开发主流语言，稳定高效 |

| **Lombok** | 代码简化工具 | 自动生成getter/setter等样板代码 |
| **SpringDoc/Swagger** | API文档 | 自动生成接口文档，方便调试 |

| **Vue 3** | 前端框架 | 国内最流行的前端框架，组件化开发 |

| **Axios** | HTTP请求库 | 和后端API通信 |

### 4.2 核心业务流程

#### 流程1：学生选课

```
学生浏览课程列表 → 点击"立即参加" → 选择班级 → 确认加入
                                              ↓
                                      数据库记录选课关系
                                              ↓
                                    按钮变为灰色"已参加"
```

#### 流程2：作业系统（教师端）

```
教师创建作业 → 添加题目（单选/多选/判断/填空/代码）
     ↓                                      ↓
设置截止时间 → 填写代码题的初始代码和参考答案
     ↓
点击"发布" → 学生端可见
```

#### 流程3：作业系统（学生端）

```
学生进入作业页 → 查看题目列表 → 逐题作答
     ↓                                      ↓
选择题点选项    填空题输入文字    代码题写代码（可选语言）
     ↓
点击"提交作业" → 答案保存到数据库 → 教师端可见
```

#### 流程4：批改作业

```
教师打开批阅页 → 看到所有提交的学生列表
     ↓
点击"查看答题" → 弹窗显示每道题的答案
     ↓              选择题：显示选了什么
     ↓              填空题：显示填了什么
     ↓              代码题：显示写的代码 + 参考答案
     ↓
输入分数 → 点击"确认"
```

#### 流程5：实训系统

```
教师创建实训 → 添加节点（树形目录结构）
     ↓              每个节点可以编辑内容
     ↓              （文字、图片、代码等）
点击"发布" → 学生端可见

学生浏览实训列表 → 点击某个实训 → 左侧显示目录树
     ↓                                      ↓
点击目录节点 → 右侧显示该节点的详细内容
```

## 八、认证与权限

### 8.1 登录流程

```
用户输入手机号+密码 → 后端验证 → 生成JWT Token
                                        ↓
                              前端存到 localStorage
                                        ↓
                        后续每次请求自动带上 Token（请求头）
                                        ↓
                            Spring Security 拦截验证 Token
                                        ↓
                              有效 → 放行 | 无效/过期 → 401
```

### 8.2 权限模型（RBAC）

```
用户 ──→ 角色 ──→ 菜单权限 ──→ 可访问的页面
  │                └──→ 按钮权限 ──→ 页面上的操作按钮
  │
  ├── 管理员 → 所有菜单 + 所有按钮
  ├── 教师   → 课程管理、作业、实训等 + 对应按钮
  └── 学生   → 用户端页面（不需要管理端权限）
```

## 十一、答辩常见问题与回答

### Q1：为什么选择前后端分离架构？
**答**：前后端分离是当前企业开发的主流模式。好处是：①前后端可以独立开发、独立部署，提高开发效率；②后端API可以同时服务多个前端（Web端、App端、小程序端）；③前端技术栈和后端技术栈各司其职，便于维护。

### Q2：为什么选择Spring Boot？
**答**：Spring Boot是Java生态中最主流的Web框架。优势是：①"约定优于配置"，减少繁琐的XML配置；②内嵌Tomcat，无需额外部署服务器；③生态丰富，整合MyBatis、Redis、Security等非常方便；③社区活跃，文档完善。

### Q3：为什么选择Vue 3？
**答**：Vue是国内使用最广泛的前端框架之一。Vue 3相比Vue 2有重大升级：①Composition API让代码组织更灵活、逻辑复用更方便；②性能提升，虚拟DOM重写；③TypeScript支持更好；④配合Element Plus组件库，开发效率很高。

### Q4：数据库有多少张表？怎么设计的？
**答**：数据库一共26张表。设计采用关系型数据库的范式设计，主要分为用户模块、课程模块、作业模块、实训模块等核心模块。每个模块的表之间通过外键关联，比如`homework_question`通过`homework_id`关联`homework`表。使用了JPA的`@ManyToOne`和`@OneToMany`注解来映射这些关系。

### Q5：登录认证是怎么实现的？
**答**：使用JWT（JSON Web Token）实现无状态认证。用户登录时，后端验证账号密码正确后，生成一个包含用户ID和过期时间的JWT Token返回给前端。前端将Token存储在localStorage中，之后每次请求都在HTTP Header中带上这个Token。后端的Spring Security过滤器拦截请求，验证Token的有效性，通过则放行，过期则返回401。

### Q6：权限控制是怎么做的？
**答**：采用RBAC（基于角色的访问控制）模型。系统定义了角色（管理员、教师、学生），每个角色关联一组菜单权限。管理端使用动态路由，登录后根据用户角色动态加载对应的菜单和路由。前端通过路由守卫实现页面级权限控制，通过自定义指令实现按钮级权限控制。

### Q7：作业系统支持哪些题型？
**答**：支持5种题型：单选题、多选题、判断题、填空题和代码题。代码题支持Python、C/C++、Java三种编程语言，教师可以设置初始代码模板和参考答案，学生可以在线编写代码并提交。

### Q8：实训系统是怎么实现的？
**答**：实训采用树形结构组织内容。教师创建实训后，可以添加多个节点，节点之间支持父子关系（类似文件夹和文件的结构）。每个节点可以编辑富文本内容，支持文字、图片、代码等。学生浏览实训时，左侧展示目录树，右侧展示选中节点的内容，通过Element Plus的Splitter组件实现分栏布局。

### Q9：项目遇到的最大困难是什么？怎么解决的？
**答**：最大的困难是在实现代码题功能时，最初使用了Monaco编辑器组件，但该组件在Vite 4环境下加载失败导致整个页面白屏。经过排查发现是Vite开发服务器返回504超时。解决方案是改用原生textarea作为代码编辑器，避免了第三方组件加载失败的风险。另外在作业提交和批改的对接上，学生端和教师端使用的题目ID格式不一致（合成ID vs 数据库ID），通过统一使用数据库ID解决了数据匹配问题。

### Q10：项目有什么可以改进的地方？
**答**：①代码编辑器目前用的是textarea，后续可以引入更轻量的代码编辑器如CodeMirror；②作业系统目前缺少自动批改功能，选择题和判断题可以增加自动判分；③缺少实时通讯功能（如在线答疑），可以引入WebSocket；④实训系统可以增加在线代码运行功能，让学生直接在平台上运行代码查看结果；⑤可以增加学习数据分析功能，统计学生的学习时长、完成率等。

## 十二、项目亮点总结

答辩时可以强调这些亮点：

1. **完整的教学生态**：从选课→学习→作业→实训→成绩，形成完整闭环
2. **5种题型支持**：特别是代码题，支持多语言、模板代码和参考答案
3. **RBAC权限模型**：角色-菜单-按钮三级权限控制，动态路由加载
4. **前后端分离**：后端Spring Boot + 前端Vue 3，符合企业级开发规范
5. **JWT无状态认证**：可扩展性好，便于后续做分布式部署
6. **Docker一键部署**：docker-compose编排4个服务，环境一致性好
7. **双前端设计**：管理端（TypeScript严谨）和用户端（JavaScript灵活）针对不同场景优化
8. **实训树形结构**：支持多层级内容组织，左侧目录树+右侧内容区，类似IDE的布局
